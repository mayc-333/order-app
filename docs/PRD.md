#커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스텍 웹 앱

### 1.3 개발 범위
- 주문하기 화면 (메뉴 선택 및 장바구니 기능)
- 관리자 화면 (재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면

### 4.1 화면 개요
사용자가 커피 메뉴를 조회하고, 옵션을 선택해 장바구니에 담은 뒤 주문할 수 있는 화면이다. 앱의 기본 진입 화면이며, 상단 네비게이션을 통해 관리자 화면으로 이동할 수 있다.

### 4.2 화면 구성

화면은 위에서 아래로 **헤더 → 메뉴 목록 → 장바구니** 세 영역으로 구성한다.

```
┌─────────────────────────────────────────┐
│  COZY          [주문하기]  [관리자]      │  ← 헤더
├─────────────────────────────────────────┤
│  [메뉴 카드]  [메뉴 카드]  [메뉴 카드]   │  ← 메뉴 목록
├─────────────────────────────────────────┤
│  장바구니                                │
│  - 담긴 항목 목록                        │
│  - 총 금액                               │
│  [주문하기]                              │  ← 장바구니
└─────────────────────────────────────────┘
```

### 4.3 헤더 (Header)

| 요소 | 설명 |
|------|------|
| 로고/앱명 | 좌측에 **COZY** 텍스트 표시 |
| 주문하기 | 현재 화면. 활성 상태일 때 테두리로 강조 |
| 관리자 | 관리자 화면으로 이동하는 링크/버튼. 비활성 상태 |

**동작**
- **주문하기** 클릭: 현재 화면 유지 (또는 새로고침 시에도 주문하기 화면 표시)
- **관리자** 클릭: 관리자 화면으로 라우팅

### 4.4 메뉴 목록 (Product Menu)

메뉴는 카드 형태로 가로 배치한다. 초기 데이터는 아래 3종이며, 서버에서 조회한다.

| 메뉴명 | 기본 가격 |
|--------|-----------|
| 아메리카노(ICE) | 4,000원 |
| 아메리카노(HOT) | 4,000원 |
| 카페라떼 | 5,000원 |

#### 4.4.1 메뉴 카드 구성

각 메뉴 카드는 다음 요소를 포함한다.

| 요소 | 설명 |
|------|------|
| 이미지 | 메뉴 이미지 영역. 이미지가 없을 경우 플레이스홀더(X 표시) 표시 |
| 메뉴명 | 굵은 글씨로 표시 (예: 아메리카노(ICE)) |
| 가격 | 기본 가격을 원 단위로 표시 (예: 4,000원) |
| 설명 | 메뉴에 대한 간단한 설명 텍스트 |
| 옵션 | 체크박스 형태의 추가 옵션 (아래 참고) |
| 담기 버튼 | 선택한 옵션과 함께 장바구니에 추가 |

#### 4.4.2 옵션

모든 메뉴에 공통으로 아래 옵션을 제공한다. 복수 선택 가능하다.

| 옵션명 | 추가 금액 |
|--------|-----------|
| 샷 추가 | +500원 |
| 시럽 추가 | +0원 |

**가격 계산**
- 항목 단가 = 기본 가격 + 선택된 옵션 추가 금액 합계
- 예: 아메리카노(ICE) + 샷 추가 → 4,000 + 500 = **4,500원**

#### 4.4.3 담기 동작

1. 사용자가 옵션(선택 사항)을 체크/해제한다.
2. **담기** 버튼을 클릭한다.
3. 해당 메뉴(메뉴명 + 선택된 옵션 조합)가 장바구니에 추가된다.
4. **동일한 메뉴 + 동일한 옵션 조합**이 이미 장바구니에 있으면 수량을 1 증가시킨다.
5. 옵션 체크 상태는 담기 후 초기화하지 않는다 (와이어프레임 기준, 연속 담기 편의).

### 4.5 장바구니 (Shopping Cart)

화면 하단에 고정된 영역으로, 담긴 항목과 총 금액을 표시한다.

#### 4.5.1 장바구니 항목 표시

각 줄에 아래 정보를 표시한다.

| 표시 형식 | 예시 |
|-----------|------|
| `{메뉴명} ({옵션}) X {수량}` | 아메리카노(ICE) (샷 추가) X 1 |
| `{메뉴명} X {수량}` (옵션 없음) | 아메리카노(HOT) X 2 |
| 우측에 해당 줄 금액 | 4,500원 / 8,000원 |

- 줄 금액 = 항목 단가 × 수량
- 옵션이 있는 경우 괄호 안에 옵션명을 나열한다 (복수 옵션 시: `샷 추가, 시럽 추가`)

#### 4.5.2 총 금액

- 장바구니 우측(또는 하단)에 **총 금액 {합계}원** 형태로 표시
- 총 금액 = 모든 장바구니 항목의 줄 금액 합계
- 예: 4,500 + 8,000 = **총 금액 12,500원**

#### 4.5.3 주문하기 버튼

- 장바구니 영역 하단에 **주문하기** 버튼 배치
- 클릭 시 장바구니 내용을 주문으로 전송 (백엔드 API 호출)
- **장바구니가 비어 있으면** 버튼 비활성화 또는 클릭 시 안내 메시지 표시
- 주문 성공 시: 장바구니 초기화 + 주문 완료 안내 (알림 또는 토스트)
- 주문 실패 시: 오류 메시지 표시, 장바구니 유지

### 4.6 사용자 시나리오

**시나리오 1: 메뉴 담기**
1. 사용자가 주문하기 화면에 진입한다.
2. 아메리카노(ICE) 카드에서 "샷 추가"를 체크한다.
3. **담기**를 클릭한다.
4. 장바구니에 "아메리카노(ICE) (샷 추가) X 1 — 4,500원"이 표시된다.

**시나리오 2: 동일 메뉴 추가 담기**
1. 아메리카노(HOT)를 옵션 없이 **담기**한다.
2. 같은 메뉴·같은 옵션으로 다시 **담기**한다.
3. 장바구니에 "아메리카노(HOT) X 2 — 8,000원"으로 수량이 합산된다.

**시나리오 3: 주문 완료**
1. 장바구니에 항목이 1개 이상 있다.
2. **주문하기**를 클릭한다.
3. 주문이 서버에 저장되고, 장바구니가 비워진다.

### 4.7 UI/UX 요구사항

| 항목 | 요구사항 |
|------|----------|
| 가격 표시 | 천 단위 구분 쉼표 사용 (예: 4,000원) |
| 활성 탭 | 현재 화면(주문하기)은 테두리 등으로 시각적 구분 |
| 반응형 | 데스크톱 기준 레이아웃. 모바일은 추후 확장 가능 |
| 빈 장바구니 | 항목 없을 때 "장바구니가 비어 있습니다" 등 안내 문구 표시 |
| 로딩 | 메뉴 목록 조회 중 로딩 상태 표시 |
| 오류 | API 실패 시 사용자에게 재시도 가능한 오류 메시지 표시 |

### 4.8 프런트엔드 상태 관리

| 상태 | 설명 |
|------|------|
| `menus` | 서버에서 조회한 메뉴 목록 |
| `cartItems` | 장바구니 항목 배열 (메뉴 ID, 메뉴명, 옵션, 단가, 수량) |
| `selectedOptions` | 각 메뉴 카드별 현재 선택된 옵션 (메뉴 ID → 옵션 ID 배열) |

**장바구니 항목 식별 키**: `menuId` + 선택된 옵션 ID 정렬 후 조합 (동일 조합이면 수량 합산)

### 4.9 API 연동 (프런트엔드 관점)

| API | 용도 | 시점 |
|-----|------|------|
| `GET /menus` | 메뉴 목록 조회 | 화면 진입 시 |
| `POST /orders` | 주문 생성 | 주문하기 버튼 클릭 시 |

**POST /orders 요청 예시**
```json
{
  "items": [
    {
      "menuId": 1,
      "menuName": "아메리카노(ICE)",
      "options": ["샷 추가"],
      "quantity": 1,
      "unitPrice": 4500
    },
    {
      "menuId": 2,
      "menuName": "아메리카노(HOT)",
      "options": [],
      "quantity": 2,
      "unitPrice": 4000
    }
  ],
  "totalAmount": 12500
}
```

### 4.10 범위 외 (Out of Scope)

- 결제 처리
- 사용자 로그인/회원가입
- 장바구니 항목 개별 삭제·수량 변경 UI (와이어프레임에 없음, 추후 추가 가능)
- 메뉴 검색·필터
- 주문 내역 조회 (관리자 화면에서 처리)

## 5. 관리자 화면

### 5.1 화면 개요
관리자가 주문 현황을 모니터링하고, 재고를 조정하며, 주문 상태를 변경할 수 있는 화면이다. 상단 네비게이션의 **관리자** 탭으로 진입하며, 주문하기 화면과 동일한 헤더를 공유한다.

### 5.2 화면 구성

화면은 위에서 아래로 **헤더 → 관리자 대시보드 → 재고 현황 → 주문 현황** 네 영역으로 구성한다.

```
┌─────────────────────────────────────────┐
│  COZY          [주문하기]  [관리자]      │  ← 헤더
├─────────────────────────────────────────┤
│  관리자 대시보드                         │
│  총 주문 N | 주문 접수 N | 제조 중 N |  │  ← 대시보드
│  제조 완료 N                            │
├─────────────────────────────────────────┤
│  재고 현황                               │
│  [재고 카드]  [재고 카드]  [재고 카드]   │  ← 재고 현황
├─────────────────────────────────────────┤
│  주문 현황                               │
│  - 주문 항목 목록 + 상태 변경 버튼       │  ← 주문 현황
└─────────────────────────────────────────┘
```

### 5.3 헤더 (Header)

주문하기 화면(4.3)과 동일한 헤더를 사용한다. 관리자 화면에서는 **관리자** 탭이 활성 상태(테두리 강조)이다.

| 요소 | 설명 |
|------|------|
| 로고/앱명 | 좌측에 **COZY** 텍스트 표시 |
| 주문하기 | 주문하기 화면으로 이동하는 링크/버튼. 비활성 상태 |
| 관리자 | 현재 화면. 활성 상태일 때 테두리로 강조 |

**동작**
- **주문하기** 클릭: 주문하기 화면으로 라우팅
- **관리자** 클릭: 현재 화면 유지

### 5.4 관리자 대시보드 (Admin Dashboard)

주문 처리 현황을 한눈에 파악할 수 있는 요약 영역이다.

#### 5.4.1 표시 항목

| 지표 | 설명 |
|------|------|
| 총 주문 | 전체 주문 건수 (모든 상태 포함) |
| 주문 접수 | 상태가 **주문 접수**인 주문 건수 |
| 제조 중 | 상태가 **제조 중**인 주문 건수 |
| 제조 완료 | 상태가 **제조 완료**인 주문 건수 |

지표는 한 줄에 나란히 표시한다. (예: `총 주문 1 / 주문 접수 1 / 제조 중 0 / 제조 완료 0`)

#### 5.4.2 갱신

- 화면 진입 시 서버에서 최신 집계를 조회한다.
- 주문 상태 변경 또는 신규 주문 발생 시 대시보드 수치를 다시 조회한다.

### 5.5 재고 현황 (Inventory Status)

메뉴별 재고 수량을 조회하고 수동으로 조정하는 영역이다.

#### 5.5.1 초기 데이터

주문하기 화면(4.4)과 동일한 3종 메뉴에 대해 재고를 관리한다. 초기 재고는 각 **10개**이다.

| 메뉴명 | 초기 재고 |
|--------|-----------|
| 아메리카노(ICE) | 10개 |
| 아메리카노(HOT) | 10개 |
| 카페라떼 | 10개 |

#### 5.5.2 재고 카드 구성

각 메뉴는 카드 형태로 가로 배치한다.

| 요소 | 설명 |
|------|------|
| 메뉴명 | 메뉴 이름 표시 (예: 아메리카노(ICE)) |
| 재고 수량 | 현재 재고를 **N개** 형식으로 표시 (예: 10개) |
| `-` 버튼 | 재고 1 감소 |
| `+` 버튼 | 재고 1 증가 |

#### 5.5.3 재고 조정 동작

1. **`+` 클릭**: 해당 메뉴 재고 +1, 서버에 즉시 반영
2. **`-` 클릭**: 해당 메뉴 재고 -1, 서버에 즉시 반영
3. **재고가 0일 때 `-` 클릭**: 0 미만으로 내려가지 않음 (버튼 비활성화 또는 무시)
4. 조정 성공 시 화면의 재고 수량을 즉시 업데이트
5. 조정 실패 시 오류 메시지 표시

### 5.6 주문 현황 (Order Status)

접수된 주문 목록을 표시하고, 각 주문의 처리 상태를 변경하는 영역이다.

#### 5.6.1 주문 상태 정의

| 상태 | 설명 |
|------|------|
| 주문 접수 | 고객 주문이 접수된 상태 (초기 상태) |
| 제조 중 | 음료 제조가 진행 중인 상태 |
| 제조 완료 | 제조가 완료된 상태 |

**상태 전이**

```
주문 접수  →  제조 중  →  제조 완료
```

- 한 방향으로만 진행한다 (되돌리기 없음).
- **제조 완료** 상태에서는 상태 변경 버튼을 표시하지 않는다.

#### 5.6.2 주문 항목 표시

각 주문은 한 줄(또는 한 카드)로 표시한다.

| 요소 | 설명 | 예시 |
|------|------|------|
| 주문 일시 | 주문이 생성된 날짜·시간 | 7월 31일 13:00 |
| 주문 내역 | 메뉴명, 옵션, 수량 | 아메리카노(ICE) x 1 |
| 주문 금액 | 해당 주문의 총 금액 | 4,000원 |
| 액션 버튼 | 다음 상태로 변경하는 버튼 | 주문 접수 → **제조 시작** 등 |

- 주문에 여러 항목이 있을 경우, 각 항목을 줄바꿈 또는 쉼표로 나열한다.
- 옵션이 있는 항목은 주문하기 화면과 동일한 형식으로 표시한다. (예: `아메리카노(ICE) (샷 추가) x 1`)
- 주문 금액은 주문 전체 합계 금액을 표시한다.

#### 5.6.3 액션 버튼

고객이 주문하기 화면에서 **주문하기**를 완료하면, 주문은 **주문 접수** 상태로 생성되어 주문 현황에 즉시 나타난다.

현재 주문 상태에 따라 버튼 라벨과 동작이 달라진다.

| 현재 상태 | 버튼 라벨 | 클릭 시 동작 |
|-----------|-----------|--------------|
| 주문 접수 | **제조 시작** | 상태를 **제조 중**으로 변경 |
| 제조 중 | **제조 완료** | 상태를 **제조 완료**로 변경 |
| 제조 완료 | (버튼 없음) | — |

> 와이어프레임에는 **주문 접수** 버튼이 표시되어 있으나, 주문이 이미 **주문 접수** 상태로 목록에 나타난다는 점을 고려해 실제 구현 시 첫 액션 버튼은 **제조 시작**으로 한다.

#### 5.6.4 주문 목록 정렬

- 최신 주문이 위에 오도록 **주문 일시 내림차순** 정렬
- **제조 완료** 주문도 목록에 유지한다 (와이어프레임 기준). 완료된 주문은 시각적으로 구분하거나, 추후 필터 기능으로 확장 가능

#### 5.6.5 빈 상태

- 주문이 없을 때 "접수된 주문이 없습니다" 등 안내 문구 표시

### 5.7 사용자 시나리오

**시나리오 1: 대시보드 확인**
1. 관리자가 관리자 화면에 진입한다.
2. 대시보드에서 총 주문, 주문 접수, 제조 중, 제조 완료 건수를 확인한다.

**시나리오 2: 재고 조정**
1. 재고 현황에서 아메리카노(ICE) 카드의 **`+`** 버튼을 클릭한다.
2. 재고가 10개 → 11개로 증가한다.
3. **`-`** 버튼을 클릭하면 다시 10개로 감소한다.

**시나리오 3: 주문 상태 변경**
1. 주문 현황에 "7월 31일 13:00 — 아메리카노(ICE) x 1 — 4,000원" 주문이 표시된다.
2. **제조 시작** 버튼을 클릭한다.
3. 주문 상태가 **제조 중**으로 변경되고, 대시보드의 "제조 중" 카운트가 1 증가한다.
4. **제조 완료** 버튼을 클릭한다.
5. 주문 상태가 **제조 완료**로 변경되고, 대시보드가 갱신된다.

### 5.8 UI/UX 요구사항

| 항목 | 요구사항 |
|------|----------|

| 로딩 | 데이터 조회 중 로딩 상태 표시 |
| 오류 | API 실패 시 재시도 가능한 오류 메시지 표시 |
| 실시간성 | 신규 주문 반영을 위해 주기적 폴링 또는 화면 포커스 시 재조회 (학습 범위 내 단순 구현) |

### 5.9 프런트엔드 상태 관리

| 상태 | 설명 |
|------|------|
| `dashboard` | 대시보드 집계 (total, received, preparing, completed) |
| `inventories` | 메뉴별 재고 목록 (menuId, menuName, stock) |
| `orders` | 주문 목록 (orderId, orderedAt, items, totalAmount, status) |

### 5.10 API 연동 (프런트엔드 관점)

| API | 용도 | 시점 |
|-----|------|------|
| `GET /admin/dashboard` | 대시보드 집계 조회 | 화면 진입 시, 상태 변경 후 |
| `GET /admin/inventory` | 재고 목록 조회 | 화면 진입 시 |
| `PATCH /admin/inventory/:menuId` | 재고 수량 변경 | `+` / `-` 클릭 시 |
| `GET /admin/orders` | 주문 목록 조회 | 화면 진입 시, 상태 변경 후 |
| `PATCH /admin/orders/:orderId/status` | 주문 상태 변경 | 액션 버튼 클릭 시 |

**GET /admin/dashboard 응답 예시**
```json
{
  "total": 1,
  "received": 1,
  "preparing": 0,
  "completed": 0
}
```

**PATCH /admin/inventory/:menuId 요청 예시**
```json
{
  "stock": 11
}
```

**GET /admin/orders 응답 예시**
```json
[
  {
    "orderId": 1,
    "orderedAt": "2025-07-31T13:00:00",
    "items": [
      {
        "menuName": "아메리카노(ICE)",
        "options": [],
        "quantity": 1,
        "unitPrice": 4000
      }
    ],
    "totalAmount": 4000,
    "status": "received"
  }
]
```

**PATCH /admin/orders/:orderId/status 요청 예시**
```json
{
  "status": "preparing"
}
```

**status 값**

| 값 | 화면 표시 |
|----|-----------|
| `received` | 주문 접수 |
| `preparing` | 제조 중 |
| `completed` | 제조 완료 |

### 5.11 범위 외 (Out of Scope)

- 관리자 로그인·권한 인증

- 주문 알림 (소리, 푸시 등)
- 매출 통계·리포트
